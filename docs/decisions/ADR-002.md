# ADR-002: Problem Section Narrative Restructure

> Date: 2026-07-24
> Status: Accepted

## Context

The Problem section ("The Problem" / "Municipal complaint systems are black boxes") describes the issue abstractly. It informs but doesn't create emotional contrast. Research across 7 story-driven landing pages (Apple, Stripe, Linear, Vercel, Framer, Arc, Notion) revealed every premium page uses contrast — today vs tomorrow — rather than problem description alone.

The sprint contract (Sprint 1B) requires every section answer exactly one user question. The Problem section's question is: "Why does UrbanPulse exist?" (or equivalently "Why do existing systems fail?").

## Decision

Replace the abstract Problem description with a **hybrid narrative** combining three approaches:

1. **Section label** → "Why Existing Systems Fail" (from Sprint 1B contract)
2. **Primary mechanism** → "One Street. Two Different Outcomes." — a side-by-side timeline comparison (concept 3: One Street, Two Worlds). Left column shows the current broken flow (gray, slow, dead ends). Right column shows the UrbanPulse flow (green, fast, resolved in 2h 31m).
3. **Emotional close** → A single-sentence coda borrowed from Concept 1 ("A Tuesday Morning"): "They didn't need another ticket number. They needed someone to fix it." — transforming the comparison from clinical to human.

## Alternatives Considered

| Alternative | Why Rejected |
|-------------|-------------|
| Concept 1 only (A Tuesday Morning) | Risks feeling like fictional advertisement without evidence backing |
| Concept 2 only (The Invisible City) | Too abstract — municipal stakeholders may not connect immediately |
| Concept 3 only (One Street, Two Worlds) | Clearest logic but lacks emotional hook without the closing coda |
| Keep current section with copy polish | Underestimates the gap — the section needs structural change, not new words |
| Full cinematic video | Performance cost, wrong for government-tech tone, not in RESOURCE_REGISTRY |
| Problem section as wall of text | Violates "one question per section" rule |

## Consequences

- **Positive**: The comparison format is instantly understandable. A stakeholder sees "Today vs UrbanPulse" and grasps the value proposition in under 5 seconds.
- **Positive**: The emotional coda creates a memorable closing note without requiring the reader to absorb a fictional story.
- **Positive**: The two-column format naturally supports responsive layout (stack on mobile).
- **Trade-off**: The section is longer than the current version. The closing sentence adds emotional weight but requires one additional line of copy.
- **Trade-off**: Two-column layouts can feel like feature comparisons. Mitigated by using timeline format (sequence of events) rather than feature bullets.
